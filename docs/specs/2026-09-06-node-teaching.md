# 节点教学交付规格

## 2026-10-08 合讲与前置承接目标

按 ADR 0024，相关知识可以合讲，概念数量本身不构成复核失败理由。九维服务讲清内容，不要求每个子概念机械重复整套段落。以下历史规格中的单概念措辞以此决策为准；运行时接通状态见当前状态文档。

备课应明确本步真正使用的知识、所需深度及承接位置：默认基础、其他节点的具体教学任务或本课先行步骤。正文生成和复核应检查实际推导、示范及活动是否在使用前获得必要说明；不能仅凭前置 key 或章节标题认定已教。用户跳过或未查看相关材料时需补足当前理解所需背景，但不把已查看、已回答或已确认笔记推断为掌握。缺口补讲沿既有辅助讲解、回看与返回位置流程，不增加评分、锁课或自动改图。

新生成框架保存 prerequisitePlan（key、knowledge、requiredFor、source、sourceKey、useStepKeys、support）。source 为 foundation/node/step/inline；默认基础引用已确认清单原文，节点限当前显式前置，先讲步骤早于使用。正文 prerequisiteSupport 保存 prerequisiteKey 和 explanation；必要的非基础知识在每个使用步骤提供说明，展示在主讲解前，适应直接进入该步骤。默认基础可直接使用，不强制重教。承接说明与正文同版本、同样核对事实及依据，空计划不豁免遗漏依赖的语义复核。

教学上下文携带前置的真实范围/任务/例子和独立的 learningEvidence（材料、查看、跳过、疑问），当前会话读取及生成取最新事实。用户理解仅引用其确认原话；这些学习事实不进入框架稳定摘要。旧框架可读，不伪造新字段；显式重备使用新契约。字段只保存于现有 JSON，不新增数据库迁移。

## 2026-10-08 明确疑点与失败续审

已提交的疑点与备课方式在 AI 调用前保存于现有 reviewJson。GET 返回 `segments[].request` 与 `knowledge.request` 供页面恢复；尚未提交的文本仍为页面草稿。同一请求省略疑点表示恢复已保存输入，更换疑点或备课方式须新请求，不能以相同标识悄然替换。框架纠错跳转同样校验原请求。

相同请求、框架和来源版本的失败候选在明确重试时继续完整校验与知识核对，不退回原错误正文；其他请求或变化来源的候选不得复用。候选来源版本独立保留，旧发布材料始终是学习记录承接的比较基准，修订后的答案不继承旧曝光。核对针对当前原文和限定条件，已修正的旧问题须核销，不能因为疑点描述仍包含旧说法而继续否定修订稿。

知识输入按互不嵌套的正文、步骤与活动分组，选中步骤时同时核对其活动。全部实际事实仍需检查，但不重复嵌入整段；引用依据必须来自提供的资料片段，“缺少资料”的说明不能充当资料依据。实现与验证结果见状态文档。

## 2026-10-07 共享问题的结构化分工

新教学单元 version=2 的 contentContributions 绑定已确认课程问题、原内容要求零基下标及本节点承担的维度。跨阶段复用分工与原节点分工共同进入教学上下文，框架看到裁剪后的本节点要求，不要求独自讲完整个共同问题。框架每步 contentAssignments 记录本步具体承担的问题/维度；正文只校验当前步骤安排，重复出现的维度不导致整问题在每段重讲。已知问题的合法本段补充维度只保留教学，不计入该问题覆盖；原始候选与规范化结果保留。未知、重复和错段标注仍拒绝，规范化后缺少的必需维度须明确报出维度及可安排段落供局部修复。框架事实纠错保留这些安排。显式局部重备可带具体疑点：先独立核对该段现有正文、参考答案及疑点反例，再有界修复；疑点本身不作为正确答案。若错误来自框架，沿原框架纠错版本承接；旧材料和交互保留。

覆盖统计从当前有效框架与材料提取位置，按节点分别核对自身分工，再在课程层面汇总要求/维度；尚未安排、待生成、失效或历史材料不冒充完成。旧version=1保持原有范围，新分工不能拿缺少分工证据的旧材料抵扣。

## 2026-10-07 课程基础与教学分工

依 ADR 0023，已确认课程方向的默认基础和新增范围、节点的新增知识/课内任务/代表例子/基础/教学引用进入版本化教学上下文。默认基础直接使用，用户可在当前步骤提问补讲，按现有辅助内容保存；不创建基础节点或能力事实。教学引用只承接回顾、比较或应用，不生成前置边。九维框架和正文复核按本节点分工判断，不强制重复教授共同引用的整项课程问题。边界变化使旧框架需要重新准备，旧材料与个人记录保持原版本。

## 2026-10-06 框架知识纠错

依 ADR 0022，框架事实核对与教学安排复核分开，知识核对给出实际主张、推导/片段依据及支持、错误或待核对结论。正文复核可定位框架错误，知识冲突先查明错误归属；框架修正创建新版本并重新检查正确正文，不要求正文迎合错误框架。旧版本、草稿、帮助和交互保留，已知错误框架停止新授课，修正失败可显式重试。一次段落请求最多进入一次框架修正；框架及正文修复仍有界，GET不调用AI。纠正依据留在服务端，公开状态不含隐藏解答。

`POST teaching` 接受显式 `verifyKnowledge=true`、可选 `concern`（最多4000字符的原文或反例）和原有请求/版本绑定；疑点是待验证输入，不自动触发改写，实际提示和独立判断留在调用日志；返回核对状态及纠正来源版本，当前框架标记需纠正时暂停新授课。原文由合法编号恢复，可对同组不同实际原文分别核对，全部目标须覆盖；明确AI JSON外壳仅一层解包，仍完整校验并分别保留原文/解析/结果。正确正文按当前契约规范化后比较，属性顺序不导致草稿和曝光丢失；实际步骤内容改变仍不继承旧解答曝光。实现及证据以状态文档为准。

## 2026-10-06 内容覆盖与自我解释

依 ADR 0021，框架和正文的内容复核使用有目标位置和原文依据的重大缺陷报告。一般建议与来源缺口单独记录，不要求消除后才继续。框架检查安排，正文检查当前段落，不索要尚未生成部分的具体例题。报告结构错误仅修复报告，不重写有效材料；最多两次材料修复，无进展提前停止，失败保留候选、完整调用和实际原因。服务端结构、九维/步骤映射及片段引用校验不变。

正文可引用当前教案已存在的内容问题来说明补充关联，不因该维度未列入登记问题的必需清单而视为未知问题。补充关联不替代登记维度的覆盖要求；未知问题、重复引用及超出本段安排的维度仍拒绝。

分段输入包含核心框架、其他段目标摘要和当前段的完整有序步骤；本次只能填充当前步骤。步骤缺失、重排或夹带其他段步骤时提供实际/允许标识的结构诊断，修复仍不能改写框架。补充解释写入当前步骤，无进展的相同结构失败提前停止并留档。

依 ADR 0020，新课程以具体内容问题、材料说明要求与九维位置追溯覆盖，规划中的 checkableOutcome 仅保留旧协议读取；新问题的说明要求不作为用户能力评判。当前有效框架/段落/步骤提供材料位置，未备课和旧版本不算已有正文。用户个人理解草稿持续保存，只有本人明确确认才能首次沉淀 seen；节点 check-answer 停用且不调用 AI。教学步骤的主动提问和可选思考反馈保持独立，不成为确认门槛。

## 2026-10-04 新协议（取代下述 v1 执行流程）

依据 ADR 0017，框架固定九维与五段安排，段落独立生成并持久化版本；交互绑定段落/步骤/材料版本，提问无需练习标识。GET 只恢复，POST teaching 准备框架，POST segments/:key 按需备课/重试/修订，PATCH 保存位置、草稿与曝光，POST interactions 保存输入后答疑，POST sources 补充或重新提取公开 HTTPS 资料。每次生成最多两次局部修复，来源不足可明确标注后讲解。用户可以跳转、跳过思考和看解答；自己的理解仍明确确认后沉淀 seen。新库不承接旧教学数据，下面的完成项和验证命令只描述历史 v1，不作为新版完成证据；本轮专门测试推迟至功能完成后。

新版运行模块为 `teachingContracts.ts`、`progressiveTeachingService.ts`、`teachingSources.ts` 和 `progressiveTeachingTasks.ts`；正式节点页由 `ProgressiveTeachingWorkspace.tsx` 执行，原组件名只转出新版入口。整课框架、段落材料与进度分别存储。框架按目标/概念上下文建立新版本；局部材料按段落建立新版本；旧交互继续引用原材料，历史框架只读。

请求契约：准备操作使用 requestId；修改/段落准备/交互带 sessionId 和 revision；段落操作额外带 segmentId 与稳定 stepKey；回答需要 exerciseKey，问题可以不提供。提示、解答曝光与材料版本绑定，尚未揭示的提示和解答不进入公开材料。PATCH 支持位置、跳过、作答/问题/个人理解草稿、补讲返回位置及疑问状态。GET 可按 sessionId 查看属于当前节点的历史框架，读取不启动生成。后台未完成请求由用户显式重试，不在读取或刷新时自动重发。

资料使用来源 URL、段落/PDF 页位置和内容 hash 定位真实片段，本地匹配概念、核心问题和当前段落目标。已生成材料保存片段快照，更新资料不改写旧材料或作答。生成状态、候选、复核和调用记录持久化，失败保留已有内容；框架或材料每次最多两次修复。摘要仅记录实际查看步骤的术语/结论、原始问题和本次反馈观察，不把 AI 观察转成用户能力事实。

新库启动选择由 `web/scripts/teaching-database.js` 统一管理，首启保留旧库一致性备份并从版本化空白 seed 初始化，以启动互斥避免并发初始化；后续复用并执行原数据库生命周期。Web 开发/生产入口、Electron 开发和 packaged 主进程均接通。功能与检查结果以状态文档为准，历史 v1 的专门测试尚未转换成新版验收。

日期：2026-09-06。实施授权：用户要求设计开发节奏并执行。术语与长期边界见 CONTEXT 和 ADR 0016，证据只写 CURRENT_PROGRESS_AND_DIFFICULTIES。

## 目标与假设

首轮在现有本地优先原型中交付一段可以持续学习的流程：用户进入已规划节点，按需获得 AI 准备的解释、示范、练习和答疑；在沉淀前作答，失败后继续；最终自己总结并确认。当前模型、资料及教学效果均未经这轮实验确认，不把工程实现描述成教会新手。

使用现有 Next.js 15、React 18、Prisma 5、SQLite、Vitest、Playwright，无新增依赖。保留旧 practice 的沉淀后语义，不自动改图、推进掌握或物化个人知识。

## 模块与接口

`web/src/lib/learning/nodeTeaching.ts` 定义公开 DTO、材料与输入解析；`nodeTeachingService.ts` 封装存储与生命周期；`web/src/lib/ai/nodeTeachingTasks.ts` 封装提示与调用。API 位于 `/api/domains/:id/nodes/:nodeId/teaching`，GET 恢复，POST 准备，PATCH 保存位置/作答草稿及揭示提示或答案；`/interactions` POST 提交回答/提问及显式重试。每次变更携带会话 ID 与 revision；交互额外带请求 ID。同一请求 ID 不允许改变内容。

组件独立放在正式学习页面目录，沿用 ActionButton/SectionPanel/StatusPill。示例：`await saveTeachingProgress(domainId, nodeId, { sessionId, revision, action: "hint", exerciseKey });`。错误使用可判断的服务错误类型，所有异步动作 finally 复位，不静默清空输入。

材料使用文本渲染；引用只来自已有课程来源，经过既有 URL 过滤，AI 返回的引用只能指向已提供来源。教学版本保留完整参考答案，公开 DTO 仅在已显式揭示时包含答案。独立练习是任务类型，是否独立完成另外根据提示/答疑曝光记录。
