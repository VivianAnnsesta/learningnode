# ADR 0029: 随个人修订保存别名及发现未引用提及

状态：已接受，2026-11-09。

## 决策

1. `KnowledgePointRevision.aliasesJson` 是个人记录别名的唯一存储，默认字符串 `[]`。新增前向迁移，既有修订得到空别名，标题、正文、来源、序号、时间和当前指针不变；不复用课程概念字段，不修改旧迁移或向旧引用快照补写元数据。空白seed由版本化生成器更新；真实用户库只走先备份后迁移及保真/外键检查的生命周期。
2. 正式个人记录创建/修订命令接受可选 `aliases:string[]`；每份输入最多20项，每项trim后非空、至多80个UTF-16单元，不接受控制字符、不完整Unicode或非字符串。保留显示文本，按 `NFKC` 后 `toLowerCase()` 的键去重。创建省略等同空数组；修订省略原样保留期望当前修订的别名，显式 `[]` 才清空。修改别名仍须 `expectedRevisionId` 和明确保存，冲突不部分写入；创建幂等比较包括有效非空别名，原无别名请求的已有幂等哈希保持兼容。
3. 当前记录DTO与历史修订返回各自 `aliases`，列表结果同时返回 `matchedAliases`。列表、快捷查找、引用选择共用唯一搜索服务：以NFKC+lower键进行字面子串匹配当前标题、正文和别名，`%`、`_`不是通配符；无当前修订的旧记录仅沿用既有标题/正文回退。别名不做全库唯一，同名记录按稳定ID分别显示。读取不得拿旧修订、来源快照或退役标题替代当前内容。
4. 搜索及提及的匹配必须先于分页，total与页面在同一只读快照中计算。采用按ID分批读取必要字段的完整扫描，不预截断候选；仅保留排序元数据，最终页才读取完整DTO/上下文。排序保持现有updated-desc/id与SQLite NOCASE标题/id语义，不能使用系统localeCompare改变顺序。只读扫描有界运行，耗尽时失败，不返回不完整的total；大库性能另在状态文档记录，不以硬top-N掩盖遗漏。
5. 新增只读 `GET /api/knowledge-points/:id/mentions?offset&limit`。响应为 `{target:{id,title,revisionId,names},mentions:{items,page}}`；items按来源记录包含 `id,title,revisionId,matchedNames,context:{start,end,quote}`。只扫描其他记录当前修订的正文，排除按现有严格快照读取规则已引用目标记录的来源。目标没有可引用当前修订时返回空候选及可见原因。正文中的任何同名不证明语义相同；同名目标各自独立。
6. 提及按NFKC+lower键匹配完整名称，英文等词名端点不得嵌入其他非东亚字母/数字/组合符/下划线词中；汉字、假名、韩文可在连续句子中匹配，英文缩写紧邻这些文字也可匹配。单字符名称仍可形成候选，用户依据上下文选择。上下文返回含首次有效匹配的完整原文段落及原始UTF-16范围，不把归一化偏移套回原文；同一来源多次命中只计一条，matchedNames保留命中的各名称。
7. 提及界面显示目标名称、来源与原文，打开真实来源记录并保留受限returnTo，提示使用已有引用选择器明确选择并保存。它不自动加入草稿、改写正文、创建语义关系、调用AI、改变地图或学习状态。编辑、409合并、历史阅读和所有搜索入口均显示正确别名；读取/刷新不能覆盖未保存的别名草稿。

## 验收

行为参考 Obsidian 官方[别名](https://obsidian.md/help/aliases)、[反向链接](https://obsidian.md/help/plugins/backlinks)与[向外链接](https://obsidian.md/help/plugins/outgoing-links)说明。项目采用已有个人修订和来源引用模型，因此提供明确标识的记录级候选及原文上下文。

纯规则覆盖Unicode归一化、字面查询、英文/中文边界、短名称、重复名称、原文段落位置和确定性排序。隔离SQLite/HTTP覆盖创建/保留/清空、幂等及409原子性、历史/引用保真、三入口统一搜索、过滤分页及尾页、只扫当前正文、同名记录、有效引用排除、无AI或其他业务写入。旧修订升级副本与空白seed须验证默认空数组、原数据不变及外键完整，再进行真实页面、打包、空白运行、升级和安全门禁。确切结果仅见当前状态文档，未验证项不得写成已完成。
