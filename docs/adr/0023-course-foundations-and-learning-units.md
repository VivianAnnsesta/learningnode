# ADR 0023: 课程基础与最小完整教学单元

日期：2026-10-07。状态：Accepted（用户明确认可方案并要求优化）。承接 ADR 0017、0020、0021。

2026-10-08：下述“一项新增概念”的严格粒度要求由 [ADR 0024](0024-teaching-coherence-and-prerequisite-continuity.md) 替代。课程基础、明确职责、共享问题分工、版本与确认规则保留；合讲本身不构成阻断，优先核对所需知识的实际教学承接。

## 决策

1. 课程方向显式保存默认基础清单和本课新增知识范围，由既有课程方向与骨架联合确认承接。基础是可修正的课程起点假设，不是学习者掌握事实；默认直接使用，用户可按需请求补讲。任务书中明确要求重学的内容优先，不能仅因某个术语通常属于较早学段而删除。
2. 节点是相对于该起点与深度的最小完整教学单元：一项新增概念、原理或方法。新增知识、课内任务、代表例子、使用的默认基础及对其他节点的引用分别保存。定义、意义、步骤与例子仍组织在同一概念的九维教学中，不机械拆成节点。
3. 新增知识只由一个节点主要负责，其他位置通过稳定 key 引用并说明用途。引用、比较、回顾不自动产生前置依赖；同义去重和粒度由语义复核判断，不能按标题连接词、词数或固定数量裁决。结构校验检查引用存在、不可自引及精确重复的新增内容。
4. 规划生成、局部修复、复核和教学共用上述边界。当前阶段修复不改写已确认课程基础、目标或其他阶段；需要调整课程起点时沿原课程方向重新规划与确认。普通重合或可优化粒度仍是建议，只有既定严重缺陷规则可阻断。
5. 课程边界保存在现有课程方向 JSON，教学单元保存在现有 concept JSON。新增版本化字段仅对新生成内容要求，旧资料可读且不自动猜测、回填或改写。读取与普通学习操作不触发地图修改。上下文纳入新字段，边界或节点变化后旧教案保留，新备课使用新版本。
6. 默认基础补讲沿既有提问与辅助讲解保存，不要求创建基础节点或进行能力评分。新生成、失败与修复继续保留调用证据；不增加无限复核或额外用户确认步骤。

## 原因

原规划将宽泛课程范围和已有基础混合，节点范围仅有自由文字，备课需要再次推断职责。显式区分课程起点与新增知识，可从规划源头减少重复教学，并使九维备课沿用已确认的教学范围。该设计不宣称自动分解已获教学效果验证。

实现及验证证据只记录于 CURRENT_PROGRESS_AND_DIFFICULTIES.md。

## 2026-10-07 补充：共享内容问题的具体分工

新增教学单元 version=2，contentContributions 逐项保存 contentQuestionKey、requirementIndices（课程问题 contentRequirements 的零基下标）、dimensionKeys 和 contribution（本节点具体贡献）。下标绑定已确认问题清单及地图版本；清单调整必须重新校验，不猜测迁移。原 version=1 或无单元内容保持旧的整问题解释，读取不自动改写。

节点可以只承担共享问题的一部分。复用节点时，ConceptReference 可保存本次明确新增的 contentContributions，由地图草稿确认承接，不私改原节点；教学上下文合并其已确认分工。课程总览汇总各节点实际材料的覆盖，并单独显示尚未安排的要求/维度；一个节点完成不得代替另一个已分工节点完成。仅有规划不算已有正文。

框架只绑定当前节点承担的内容要求与维度。分段备课须在框架中明确将本节点的各内容问题/维度安排到具体步骤，正文逐步校验该安排，不要求该维度在每个段落重复覆盖同一问题。九维课程结构仍保留，内容问题只约束本节点承担的贡献。有效材料位置记录原要求下标，引用是可追溯的位置证据，实际内容正确性仍由内容复核及后续实测判断。

## 2026-10-08 补充：教学维度与覆盖计数分离

步骤可以教授整课九维中的补充内容，内容问题的必需维度只限定哪些标注可计入该问题的覆盖。对于已知问题及合法本段维度，系统将 contentAssignments 规范化为与本节点问题维度的交集；交集为空时不计入覆盖，步骤目标和九维教学内容保持。原始候选与规范化结果分别保存在调用日志，不能把规范化称作知识纠正。

未知或重复标识、超出本段的维度仍属于结构错误。规范化后仍须完整安排本节点承担的全部问题维度，正文仍逐步核对实际安排；不得自动添加缺失要求、扩大节点职责或以额外讲解替代必需覆盖。

## 2026-10-08 补充：已确认阶段的可修订入口

已展开阶段可从现有正式内容建立修订草稿，用于纠正新增知识、教学任务或概念范围。保存仍调用绑定当前 mapRevision 的 Map Draft，审查通过后由用户明确确认；编辑与刷新不修改正式地图。刷新须恢复 expanded 到 expanded 的修订草稿，保留草稿中的其他阶段、稳定节点 key、教学引用和显式前置关系。已开始或已沉淀节点沿既有事务 reconcile 保留身份与学习记录，不得经修订入口删除。

结构化分工的标识和下标保持原约定，文字纠正不能冒充新问题分配；真实事实错误与模型报告均保存为证据，复核通过仍不等于知识获得权威认证。
