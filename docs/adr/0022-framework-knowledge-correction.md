# ADR 0022: 知识事实核对与框架纠错

日期：2026-10-06。状态：Accepted（用户要求修复已经说明的框架事实核对与纠错闭环）。承接 ADR 0017、0018、0021。

## 决策

知识报告的原文引用优先使用系统提供的原文编号，由系统从候选恢复真实文本；保留历史文字引用的校验兼容。不得要求模型复述多个要点后再把真实但合并的文字当作伪造引用。编号越界、伪造资料及明确不匹配的引用仍拒绝。

全部固定知识目标必须被核对，但一个目标可以返回整组结论，也可以对不同实际原文分别核对；不能因更细的合法核对超过固定组数而阻断。每条核对绑定原文位置，同位置重复和缺失目标继续拒绝，报告数量上限由实际候选原文数量决定。

教学 AI 返回如只含明确的 `{type:"json_object", content:实际对象}` 外壳，可以取其中的实际对象接受完整校验；原始返回和解析结果仍按原样保存，校验结果另存。仅识别这一层确切格式，不猜测其他字段、不删除缺陷、不跳过九维、引用或版本门禁。用户请求和其他业务协议不因此改变。

复用正文并承接学习记录时，按同一当前契约规范化后比较步骤内容；JSON 属性顺序不是材料变更。数组顺序、参考解答、提示、提问、引用等实质变化仍视为变更，不继承旧题曝光。相同步骤承接草稿、帮助、已读和跳过记录，原记录仍绑定原版本。

1. 教学安排与知识事实分别检查。框架中的定义、贯穿案例、九维要点和各段目标接受独立知识核对；核对输入只包含实际主张、概念范围及提供的资料，不携带先前通过标签或要求服从框架的结论。核对先给出推导或资料依据，再判断支持、明确错误、依据不足或纯教学安排。所有目标均须有记录，但不要求产生错误或补充内容。资料不足明确标注，不直接判为知识错误；模型判断不是权威证明。
2. 正文复核允许定位框架中的上游错误。出现知识冲突时，再核对涉及的原文与框架事实，区分框架错误、正文错误及复核错误，不能只因正文与框架不同就改写正文。知识复核需实际原文、可检查推导或提供的资料片段；错误意见与撤销理由均留档。
3. 已公开框架的知识修正创建新的框架版本。修正只更新有依据的事实及受影响说明，保留概念、范围、前置要求、九维映射、段落和步骤身份，不通过扩充课程消除缺陷。修正前后和依据记录在现有会话/复核 JSON 与 AiCallLog，不新增表或迁移。正式地图与课程目标不受教学修正改写。
4. 已知有重大事实错误的框架停止用于新的授课操作，旧框架、段落、草稿、曝光和交互保留供历史回查。新框架继承个人理解草稿；旧作答继续绑定原版本，不改写为新答案或新能力事实。当前正文若已正确，先在新框架下重新校验与复核，不能强制重新生成来迎合旧框架。其他已有段落按需重新检查，尚未生成段落继续按需准备。
5. 一次段落请求最多进入一次上游框架修正。框架/材料修复仍最多两次，无进展提前停止。框架修正失败保留原始错误、候选和调用，提供显式重试；GET 与刷新不调用 AI。相同请求复用修正任务，过期目标、来源、会话版本或生成令牌不能覆盖新结果。
6. 框架事实核对和修正状态落库，读取提供不包含隐藏答案的状态说明及版本承接信息。页面仅补充必要纠正状态/操作，复用现有入口，不做视觉改版。结构、安全、来源访问、个人确认沉淀及版本门禁保持。

## 原因与代价

微积分实测中，错误框架将相同函数说成不同函数；复核把正确答案当作错误，替换题目后保留错误框架并通过。只检查内部一致性会放大生成错误，当前段落修复也不能处理上游事实。分别核对事实与安排、记录错误归属并版本化修正，才能让错误回到产生位置。独立核对增加调用与延迟，资料不足和模型判断仍需明确局限，不能宣称消除了幻觉。

实现状态与验证证据仅记录在 CURRENT_PROGRESS_AND_DIFFICULTIES.md。


## 2026-10-08 补充：带具体疑点的显式核对

现有 POST teaching 的 verifyKnowledge=true 可带可选 concern（最多4000字符），由课堂中的“待核对的原文或反例”输入。它是待检验主张，不是修改指令或可靠事实；知识核对必须针对原文、条件和所给反例作独立推导，不能仅以措辞合理为由略过反例，也不能因用户提出就判定错误。实际提示及报告通过现有 AiCallLog 留存。只有原有知识错误报告成立才生成纠错版本；不绕过来源、版本、内容校验或保留门禁，无数据库结构变化。


同一疑点机制用于现有 POST teaching/segments/:key 的显式 reprepare=true：可带 concern，服务端读取该段当前已发布材料作核对候选。先独立核查具体疑点及正文事实，再由既有有界修复/内容复核生成材料版本；不直接采纳用户的“正确答案”。若错误源自框架，沿既有框架纠错及版本承接处理。旧正文、题目解答曝光和交互不被改写；改过的步骤不能沿用原解答曝光。新字段只传递核对上下文，沿现有日志保存，无新数据库模型。

显式核对在调用 AI 前把请求标识、原始疑点及所核对材料身份保存于现有 reviewJson；检查点、完成或失败不能覆盖该请求快照。GET 恢复提交过的疑点和请求状态，不触发 AI。失败重试复用原请求及疑点，省略疑点表示恢复已保存输入，同一请求标识携带不同疑点必须拒绝；修改疑点由页面创建新请求，原请求记录保留。整课知识核对沿用相同规则并保留历次请求摘要，不能刷新后把带疑点核对悄然变为普通重备。尚未提交的文本仍是页面草稿。

同一请求在当前框架及来源版本下失败或中断，若已有请求快照和已保存正文候选，明确重试先恢复该候选执行完整结构、引用和知识核对，再继续有界修复；不能退回原错误正文重做。其他请求、其他会话或已变化来源的候选不得复用，候选原来源版本保留至新候选实际写入。原 sourceMaterialId 始终表示首次核对的已发布版本；恢复候选不改变该身份，旧草稿及曝光仍只按原发布步骤与最终正文实际相同而承接。

知识核对目标去重不能丢失被指控的事实。正文步骤被选为复核目标时，同时展开该步骤所属的活动目标，保留问题、参考答案、回应依据和提示供独立核对；各目标仍只保存自己的内容而不重复嵌套。选择整段时核对全部目标，选择单个活动时只核对该活动。
