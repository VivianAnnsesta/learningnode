# ADR 0019: 阶段修复限定范围并保留课程目标

日期：2026-10-05。状态：Accepted（用户明确要求补齐返回约定，并让阶段修复只修改当前阶段）。承接 ADR 0013、0014、0017、0018。

## 决策

1. 阶段展开及其后续复核的修复范围绑定服务端草稿中的 Stage key。内容复核可以检查整图，但阶段修复只返回 `{ report, stage }`，不得返回整张地图或课程级字段。Stage 必须是当前草稿中已展开的目标阶段，稳定 key 与展开状态不能改变。
2. 服务端从当前版本的完整草稿合并目标阶段，原样保留领域 learningGoals、地图元数据及其他阶段。目标阶段可以修订教学蓝图、概念内容与显式前置，但仍须通过整图的目标覆盖、概念复用、引用、DAG、版本和既有成果保留门禁。局部修复不能把其他阶段的明确复核问题宣称为已解决；原意见保持原文，修复时的重复转述不能累加为新问题。只剩明确指向其他阶段的意见时停止局部修复，保留阻断及用户原有处理入口。
3. 整图复核修复及骨架修复的返回示例明确包含 learningGoals。持久化整图修复不能删除、替换或改写已有课程目标；若需要修改课程目标，仍走既有规划变更与用户确认流程。
4. 结构及领域校验异常统一转为带精确问题的 AI 校验失败，进入携带失败原文和候选的有界结构修复；每次实际调用独立留档。修复次数不无限增长，耗尽后继续阻断错误草稿，不降低业务门禁。
5. 正式 Domain API 的阶段复核请求读取 Stage key，必要时从仍与当前草稿摘要、mapRevision 及课程依据匹配的复核记录恢复该范围。复核记录保留目标 Stage key，即使审查范围为整图。读取、刷新和重试仍不自动确认正式地图。

## 原因与代价

真实阶段展开在修复时重写完整地图，返回格式示例遗漏课程目标，模型随后也省略该字段。阶段任务不应承担重复输出已确认课程级内容的责任。局部返回减少无关改动与输出负担，但服务端仍需整图验证，并保留超出当前阶段的复核意见，防止将局部修复伪装成全局内容通过。

本决策不新增建图路径，不修改数据库结构，不绕过用户确认，也不把模型复核当作知识正确性证明。实现状态与验证证据仅记录在状态文档。
