# ADR 0032：修订拥有的本人记录日期与只读月历

状态：接受；日期：2026-11-09。

## 决策

1. `KnowledgePointRevision`新增可空TEXT字段 `recordDate`、`recordDateTimeZone`。两者皆null表示未指定；有效值为真实公历YYYY-MM-DD（0001至9999）和显式Intl支持的IANA名称/别名或UTC。API表示为 `recordDate:{date,timeZone}|null`，日期/时区形状完整、无未知键，保持有效时区输入名称，不接受数值偏移或前后空白。本人日期是用户的归档选择，不是时间戳，不转换为UTC午夜，不表示学习事件。一天可多条记录，不建单日正文容器或唯一每日笔记。
2. 日期只由原个人记录创建/追加修订writer写入。创建省略或null均保存两列null，旧无日期幂等hash不变；只有非null日期才条件加入创建hash。修订省略日期时精确继承expected当前修订的两原列，包含不可读取旧raw，不从latestSequence或时间戳猜值；显式null同时清空，完整有效tuple明确新增/修改。现有修订使用expectedRevision CAS，没有独立requestId/hash账本，本批不另建该账本或改变该边界。改变/清空日期也追加不可覆盖修订，不UPDATE旧row。原来源保留、别名及创建幂等/修订CAS不变，不新增日期专用PATCH绕过记录保存。
3. 当前及历史DTO分别给出各自 `recordDate` 和可选 `recordDateUnavailableReason`。双null为未指定；半tuple、坏日期、坏时区等读为不可用且保留原raw，不静默修复、转换或回填。本人日期范围/月计数只匹配有效当前修订日期；未指定或不可用不匹配，普通不限日期阅读仍可看记录并显示问题。正文保存而未编辑日期时不被旧坏日期阻断；只有用户明确日期编辑/清空才替换该元数据。原固定来源快照/段落选择器不扩入日期或改写旧快照。
4. 既有日期合同只扩展 `field="recorded"`，创建/更新日期语义、默认值和旧SavedKnowledgeView schema1完整形状不变。本人日期按保存的日期字面与范围比较，跨时区浏览不改变归档日；相对N天仍按查询时区、请求内同一个now计算今天/公历日窗口。mode=all保持不筛日期，允许未指定记录继续出现。只读显示字段追加recordDate，保持所有旧字段次序及默认字段不变；损坏日期显示不可用而非假装未指定。日期校验及timezone缓存须有界，不为每条记录重复创建formatter。
5. 新只读正式入口 `/api/knowledge-points/calendar` 使用与列表相同的q/domainId/collectionId/kind/sourceType/sort基础筛选，外加可选month=YYYY-MM、dateField(created/updated/recorded)、timeZone。只接受这些白名单参数，重复/未知/无效参数拒绝；不接受dateMode/dateFrom/dateTo/dateDays/display fields等，以免把单日范围混入月统计。未给month时由请求同一个now与指定时区决定当前月。按记录当前修订去重，完整基础匹配后在同一只读快照/有界分批扫描统计整月，不能预截断候选。响应给month、field/timeZone、today、完整日计数、total、month的dateWindow、基础filters，以及recorded口径未指定/不可用日期计数；失效领域/主题保持原条件并返回空计数与明确原因，不静默扩大。
6. 月历是月概览，明确显示“不套用当前日期范围；选日将用该日替换范围”。它与列表共用已应用的基础筛选、日期依据和时区；点击某日将既有date切为该日双端range，因此该日count须等于新列表page.total。日期草稿尚未应用时不可通过月历选日覆盖，须先应用或恢复；月份浏览本身仍只读。计数迟到响应淘汰，读取失败不显示假零。记录创建/更新日期按时区转换，recorded口径不转换日期；切换浏览时区只影响today/相对窗口与时间戳口径。范围跨日继续分页沿用现有dateWindow变更重读首页保护。
7. `calendarMonth`为严格校验的可选URL阅读状态，进入共同解析/序列化、安全returnTo与引用/图谱/Ctrl+K返回，不能由组件私加后被normalize丢失。它不属于SavedKnowledgeView config、不扩展旧schema1必填字段；保存视图仍保存实际date过滤。打开保存视图时可从其范围起日恢复对应月，否则读取当前月；普通月份导航不修改现有日期范围、正文或草稿归属。日历只读入口必须可发现，未加载计数与0区别显示。
8. 两正文入口共用本人日期编辑器，日期可选、允许补写，时区明确，清空需明确动作；空记录不因打开日期而自动保存。月历选日只改变检索；“为这一天填写记录”才明确设置新记录的日期草稿，保留已有标题/正文/类型/别名/来源和保存领域，不暗造标题或正文。日期本身属于新记录草稿，已有日期后切换视图不能移动保存领域。成功保存沿用原标题/正文/别名清空行为但保留新建表单日期，重新填写同输入时仍使用原创建幂等标识；模板撤销仍按原成功保存重置。
9. 修订日期草稿与当前展示数据分开。409展示最新日期但保留本地日期编辑；明确采用最新保存基础时，未编辑日期跟随新基础，已编辑/清空的日期草稿仍保留。日期本身无效时显示可修正错误，不丢正文；旧不可读日期在未编辑时省略提交保持raw，不以空输入默清。历史显示每个修订自己的日期及其时区/不可用状态。模板 `{{date}}/{{time}}`仍指预览时刻，不伪造now冒充补写日期，不自动赋日期；新日期字段也不写活动、完成、掌握或正式地图事实。
10. 只新增31前向迁移，不回填旧修订；原全行不可覆盖trigger继续覆盖新列。先归档schema30并校验原远端blob，固定既有27→28/28→29/29→30边界；空seed副本逆投影只移除已知空31字段/ledger，未知未来、字段失配或非空修订拒绝。新30→31验证原所有字段/两类配置/30ledger/精确备份保真，旧日期均null；日期新增/修改/清空通过INSERT新修订、更新当前引用，旧raw不变且直接UPDATE仍拒绝。重开/重复生命周期及FK/完整性继续门禁；官方空白seed由CI生成取回核验后更新，不触碰真实用户库。

## 验收与依据

参考Obsidian官方[Daily notes](https://obsidian.md/help/plugins/daily-notes)的日期入口与模板协作，适配本项目个人记录、不可覆盖修订和明确保存边界。月概览与本人归档日期不能用timestamp筛选冒充，也不能把写作日期当作实际学习事实。

纯合同覆盖真实日期/闰年/时区/字面日期、month边界/URL旧配置兼容、时间戳和recorded匹配；隔离SQLite/HTTP覆盖省略/null/tuple、旧hash/来源/别名保留、修订CAS、坏raw首次INSERT、不回填、月计数/分页同口径及范围切换、失效条件和0读取写入。真实页面覆盖回看/补写/清空/重载返回、多条同日记录、领域草稿保护、模板now不变、历史与409日期恢复；原迁移、seed、打包、升级和安全门禁保留。数量、实际结果与限制仅记当前状态文档。
