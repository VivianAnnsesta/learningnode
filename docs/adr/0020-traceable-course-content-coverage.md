# ADR 0020: 可追溯的课程内容覆盖与用户自我解释

日期：2026-10-06。状态：Accepted（用户明确要求按已讨论方案调整）。承接 ADR 0017、0018、0019。

## 决策

1. 暂不引入阶段学习成果评价。节点的自我解释仅由用户保存、修订和明确确认，首次沉淀仍为 seen；不再提供或调用该解释的 AI 复核。针对具体教学步骤的主动提问与可选思考任务反馈仍保留，不得把反馈、阅读或查看解答作为沉淀条件。
2. 阶段内容覆盖表示“本阶段安排了哪些内容来回答课程总目标下的哪些问题”，不表示用户已掌握，也不证明材料正确或课程绝对完整。
3. 在 planningVersion=3 上新增 contentCoverageVersion=1 返回契约。learningGoals 保留稳定 key 与目标原意，并保存 contentQuestions：稳定 key、具体问题、需要提供的说明 contentRequirements、所涉及的九维 dimensionKeys。这些要求描述材料内容，不规定用户提交什么或达到什么分数。
4. 模块 keyQuestions 保存稳定规划问题 key 与 contentQuestionKey，引用课程内容问题。问题文本、内容要求、维度及 goalKeys 由服务端从内容问题登记表恢复；模块与阶段的 goalKeys 由系统汇总，不再要求 AI 重复声明父子目标集合。每个总目标必须有内容问题，每个内容问题必须有安排；未知引用、重复标识、缺少说明或非法维度仍阻断，不能以自动汇总代替语义与来源审查。
5. 已安排、已生成材料、待补充分别记录。展开阶段后由 planningQuestionKeys 或概念复用引用定位概念；材料覆盖依据当前有效框架、段落材料版本及步骤维度形成位置引用。同一内容问题由多个概念承接时，需要分别存在这些概念的材料位置，不能用其中一个概念的正文代替其余安排；显式复用的同一概念只计算一次。未展开或尚未备课不冒充已有正文；缺少要求的维度、旧框架或失败生成不算已生成完整材料。状态是课程内该内容问题的材料可用性，页面同时展示未展开安排、待补充概念及实际位置。
6. 课程总目标及内容问题登记表在局部修复中为只读，由服务端保留。修复只处理当前范围内的安排与引用，合并后仍检查整图；正式地图继续经过版本绑定的草稿复核和用户确认。初始整体规划仍保留完整阶段方向，不转为人工建图或隐式单一路径。
   初始骨架的引用问题能定位到单个阶段时，结构修复只返回该阶段，由服务端保留总目标、登记表及其他阶段。登记表本身无效或缺陷跨阶段时仍使用有界整体修复，不能把未知范围强塞进某一阶段。
7. 新内容存入既有 JSON 字段；本轮不新增数据库表、不重写迁移、不清空学习库。旧记录可读取，但其旧目标标签和 checkableOutcome 不被宣称为新版内容覆盖证据。新生成必须使用新版契约，旧草稿需要重新规划才能取得新版登记表。
8. 每次 AI 原文、候选、检查及修复继续独立留档。结构覆盖齐全与实际教学质量验证分开记录；真实新手效果和数学内容准确性不能由引用计数或模型复核代替。

## 原因与代价

父阶段和子模块重复填写同一目标集合，会因标签遗漏阻断一份内容可能合理的规划。把内容问题作为唯一可追溯登记表，系统计算汇总关系，可以把修复定位到缺少安排或错误引用。登记表仍需对照范围和资料检验全面性；同一问题下的概念及段落需要真实内容审查。用户自我解释不承担 AI 评判后的成果认证。
