# ADR 0027: 个人知识的引用发现与局部阅读

状态：已接受，2026-11-08。

## 背景

借鉴 Obsidian 的反向链接、局部图谱、快速查找和属性视图，让已有个人记录更容易找到、回看和复用。沿用 ADR 0025 的稳定记录身份、不可覆盖修订及唯一业务写入；不复制其文件存储架构，也不引入高级画布编辑器。

## 决策

1. 记录间的内容引用继续使用个人修订中已有的 `sources`，由用户明确选择真实记录及修订，通过现有创建/修订命令保存快照。不把正文中同名词、链接或引用自动解释为语义关系、地图前置或掌握证据。
   修订时保留未改动的既有服务器来源快照，不因增加记录引用而重新抓取旧会话、曝光状态或材料。显式提交的来源与期望旧修订的服务器条目完全一致时沿用旧快照，其余条目仍需真实来源校验；不能靠客户端自报快照绕过来源身份和版本检查。
   为避免合法的大来源快照超过既有 64000 字符请求边界，修订来源可用 `{kind:"retained",sourceIndex:n}` 指向 `expectedRevisionId` 的服务器来源数组；服务端核验该修订属于本记录及索引有效后沿用原快照。新记录引用只提交记录/修订身份，由服务器取得原文；不放宽请求上限，也不接受跨修订索引或伪造快照。
   引用编辑保留当前记录的 AI 摘录或来源摘录分类，明确保存仍表示本人接受新修订；不能因添加引用就把已有 AI 内容改记为用户原话。
2. 新增只读 `GET /api/knowledge-points/[pointId]/context`，提供当前修订的向外引用与引用本记录的反向引用。反向引用只统计引用者的当前修订，按记录去重、数据库分页，保留被引用修订身份及当时原文。历史引用在历史修订中继续可读，不伪装为当前引用。目标不存在返回 404。
3. 新增只读 `GET /api/knowledge-points/[pointId]/neighborhood?depth=1|2`，从真实记录身份出发，仅沿用户已确认的普通联系展开；候选和拒绝不参与。保留联系方向、类型与说明。最多返回 80 个记录、120 条边，任何截断明确展示，不把不完整结果写成全图。默认深度为 1，孤岛也可正常打开。
4. 个人记录列表保留现有数据库搜索、领域/主题筛选及分页，增加六类 `kind` 筛选与 `sort=updated_desc|title_asc`；非法参数返回 400。筛选与排序在分页前执行，查询状态进入 URL，刷新和返回可恢复。同一记录在不同视图中保持同一身份，不复制正文。
5. 阅读界面显示向外引用的固定修订快照、反向引用上下文、节点/领域/主题入口与可点击局部联系。引用选择可搜索更多记录，不限于第一次列表页。快捷查找和预览只读取正式 API，不调用 AI、不写学习事实，不把未提交编辑覆盖掉。
6. 沿用 Electron 本地 API 的认证、Host/Origin 和随机端口边界。所有新增读取有界，内容按文本显示，不把 AI 或用户输入当 HTML、未验证外链或可执行代码。

## 连续优化范围

本决策先接通引用阅读、局部联系、查找和类型视图。段落锚点与嵌入、别名和未链接提及、更多属性视图、可选模板、日期回看、剪藏及可携带导出继续按真实使用证据推进；这里不把这些后续方向写成已实现能力。发布使用经过验证的源代码批次，凭据、用户数据库和构建产物不得上传。

## 验收

使用隔离 SQLite 验证引用版本、当前修订反向索引、分页和筛选、跨领域确认关系、深度及截断；通过真实页面验证引用选择/保存/回看、局部跳转、筛选恢复和失败重试。精确执行证据只写入当前状态文档，不把工程通过当作学习效果证明。

针对本批能力增加独立 GitHub Actions 验证，与既有全量及桌面门禁并行保留。若本机安全策略阻止原生数据库引擎加载，记录实际阻断并使用 CI 的隔离环境继续验证，不关闭系统安全策略、不把静态检查替代数据库或页面通过，也不把源码分支发布当作桌面发布合格。
