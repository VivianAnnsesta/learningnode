# ADR 0024: 合理合讲与前置知识承接

日期：2026-10-08。状态：Accepted（用户明确允许为学习质量合讲相关概念，并要求避免突然使用尚无教学承接的知识）。承接 ADR 0017、0021、0023；替代其中严格一概念一节点的粒度要求，其余版本、安全、来源与用户确认边界保持。

## 决策

1. LearningNode 是范围明确、可完整讲解的教学单元。可以教授一个概念，也可以围绕共同问题合讲一组相关概念、原理或方法。不能仅凭概念数量判定不合格，也不能因模型声称适合合讲就认定质量合格；需明确所含新增知识、各自条件、差别、例子和使用方式。是否拆分服务于实际教学质量。
2. 九维是备课视角，用于检查讲解是否有助于理解和使用。合讲可共享动机、案例及整体位置，同时讲清不同知识的关键差别；不要求每个子概念机械重复九个段落。已确认的具体内容要求仍须落实，不能以合讲为由删去条件、依据或必要解释。九维齐全不等于学习透彻或用户掌握。
3. 每一项被实际使用的必要知识，都应有明确承接：课程约定的默认基础；其他节点实际承担的内容；当前课在使用前安排的讲解；或尚未安排的缺口。默认基础是可修正的入门假设。标题、显示顺序、前置 key 存在或宽泛的“基本性质”字样，均不能证明所需知识已被讲解。
4. 规划只证明知识已安排，框架明确它在哪一步先讲，正文检查是否在推导、示范或任务使用之前实际解释。不能用未生成正文冒充已讲材料，也不要求阶段规划提前生成全部正文。仅预告后续用途或提及关联术语不必增设前置；只有理解或执行当前内容确实依赖它时才检查承接。
5. 教学安排与学习者理解分别管理。材料已生成、页面已查看、任务已跳过、用户自述理解或仍有疑问是不同事实；都不能自动升级为掌握证明。用户跳转、未读或表示不理解时，提供足够的前置说明、可选回看与返回原步骤的路径。简单提醒在当前步骤补讲，超出简短补讲范围的必要新知识由合适课内安排或前置节点承担；不把新增微积分知识冒充高中基础，不强制考试或锁定课程。
6. 复核针对具体的教学断层：指出哪里使用了什么、所需深度、现有承接为什么不足，以及不修复会怎样妨碍理解。没有实质后果的粒度偏好、可替代教法和措辞仅为建议。不能为消除所有建议不断补充课外知识；局部修复只处理真实缺口，保持原课程范围、总目标及其他阶段。
7. 必要节点依赖仍显式声明并经版本化草稿确认；回顾、类比和关联不自动生成地图边。补讲不自动改图，不替代用户自己的理解及首次 seen 确认。知识错误和虚假来源支持仍按既有质量规则处理。

## 实施边界

本决策不规定新增掌握评分或新的数据库模型。先对齐规划、框架、正文和复核的知识承接规则，再确定必要的结构化表达与验证。文件中的决策是目标；运行时接通和实测结果只记录于 CURRENT_PROGRESS_AND_DIFFICULTIES.md。

## 实施契约

沿用现有 JSON 和材料版本。新生成框架增加 prerequisitePlan：稳定标识、所需知识、使用目的、使用步骤、承接类型（默认基础/前置节点/本课先行步骤/当前步骤补讲）、来源标识与承接说明。默认基础引用课程确认清单，节点引用仅限显式前置，先行步骤必须真实存在且先于使用；系统验证引用与顺序，语义复核检查内容和深度是否真正满足需求。空清单允许，但复核仍须检查正文中遗漏的真实依赖。

新框架的正文步骤保存 prerequisiteSupport，绑定实际需要的计划项并给出在使用前呈现的简短解释。默认基础可直接使用；其他必要知识在每个使用步骤提供足够的就地说明，使跳步或重读不依赖虚假的“已经掌握”。这些说明与正文同版本、接受同样的事实/来源检查；不新增自动掌握状态。已有框架保持可读，显式重新备课才采用新契约，不能给旧材料伪造承接记录。

备课输入包含前置节点的范围、新增知识、教学任务与例子，并另附最新材料/查看/疑问事实及用户确认的理解原话。学习事实随请求刷新，不参与稳定框架内容摘要；普通阅读和作答不导致教案失效。节点教学范围变化仍须形成新框架版本。
