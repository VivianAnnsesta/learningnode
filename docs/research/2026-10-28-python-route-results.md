# Python 列表路线实测：语义、边界与保存审读

日期：2026-10-28。实验已终态；本报告独立审读 thinking 的完整候选及 direct 停止前全部可得产物。未到达的产物不判为生成内容错误。本报告不修改被冻结的输入、判据、生产代码或模型产物，不新增模型调用。

本次 thinking 候选把别名、浅拷贝、嵌套修改和重新绑定的核心区别讲对了，deepcopy 也没有变成主线前置。四个 Stage 的响应与重载草稿逐一相同。但课程、骨架和三个 Stage 的独立知识核对未完成。direct 的已展开核心例子也正确，第二阶段因真实语义复核不可用而停止，第三阶段未展开。两者都不能记为整条路线知识核对与真实教学效果达标。

## 证据范围与判断方式

原始证据位于 [完整路线实验目录](../../web/test-results/route-quality-live-2026-10-28-1793183197873/)，主要读取 `manifest.json`、`oracle-frozen.json`、两模式的 `planning.json`、`stage-N.json`、可得 `stage-N-reloaded.json`、`domain.json`、`logs.json`，thinking 的 `final.json`，direct 的 `stopped.json`，以及 `transport-requests.json`、`run-complete.json`、`cleanup.json`。下文 Stage 编号从 1 开始，JSON 的数组下标从 0 开始。

这是研究者模拟目标，不是真实学习者数据：已会变量赋值、列表下标与简单 for 循环；希望预测普通内置 list 的赋值、浅拷贝、嵌套修改，并解释共享层级；深入 deepcopy 选学，不先要求类设计或内存管理。输入材料包含官方 copy 文档的研究者转述及两段具体代码；这是一项有材料支撑的窄域规划研究，不是模型从零发现知识的测试。

判据在调用前冻结：区分事实正确、目标覆盖、真实前置、可执行例子、选学边界、来源支持与保存。规划阶段的教学提示不一律当成可直接布置的完整练习；没有具体材料的探索提示标为待具体化。不会因某字段含“掌握”就推断产品进行了掌握认证，也不会要求一概念一节点或每个节点强制练习。未出现实际学习会话、作答、延迟保持或迁移表现，因此不能检验学习效果。

## Thinking 路线：内容审读

最终候选有四个 Stage、九个节点：主线为 2 + 2 + 2 个节点，选学 Stage 为 3 个节点。以下判断基于实际展开文本，不只看内容登记或质量报告的 `passed`。

| 已展开内容 | 实际证据与人工判断 |
| --- | --- |
| Stage 1：名称绑定与别名 | `a=[1,2]; b=a; b.append(3)` 得到两个名字都读到 `[1,2,3]`；随后 `b=[9]` 只改变 b 的绑定，a 保留旧列表。两节点明确区分修改对象和改变名字指向，没有把赋值讲成复制。append 在使用前补讲。 |
| Stage 2：浅拷贝的外层与内层 | `copy()` / 完整切片新建外层、保留元素引用；平铺列表 append 的隔离只来自不同外层，不声称元素也复制。嵌套例子解释 a、b 外层不同但 `a[0]`、`b[0]` 指向同一内层。下标层级有局部演示。 |
| Stage 3：修改内层与替换槽位 | 完整初始化 `a=[[1],[2]]; b=a.copy()`，顺序执行 `b[0].append(9); b[1]=[7]`。实际正文与任务均给出 a=`[[1,9],[2]]`、b=`[[1,9],[7]]`，解释第 0 槽仍共享、第 1 槽指向不同内层，外层一直不同。没有把第二步说成修改原内层，也没有说 b 名字重新绑定到另一外层。 |
| Stage 3：可复用判断过程 | 依次检查外层、逐槽内层引用、操作目标；分别用于别名、平铺浅拷贝、嵌套浅拷贝。教学任务已带具体初始化和核对结果，虽 `example` 字段是概述，结合本节点材料可执行。相似例子留给后续生成，没有把未生成例子宣称为已完成教学。 |
| Stage 4：id/is、deepcopy、memo | id/is 为观察身份的选学工具；普通嵌套 list 的 deepcopy 例子正确给出副本内层 append 不影响原列表，任务先说明 `import copy`。memo 以自引用列表解释记录已复制对象、避免重复与递归循环；不要求手写实现。未把类协议、引用计数或垃圾回收纳入必修。 |

本审读在本地 Python 中独立执行了上述别名、重绑定、平铺浅拷贝、嵌套顺序操作、deepcopy 和自引用复制小例子，结果与这些具体主张一致。它验证的是这些普通内置 list 实例，不能外推到任意对象的自定义复制语义。

前置衔接有实际内容依据：Stage 2 使用 Stage 1 的名字绑定；Stage 3 使用浅拷贝的外层新建、内层共享；选学 Stage 使用前序概念作对比。没有主线 Stage 或主线节点依赖选学 Stage。部分前置边可更精简，但没有观察到仅按排序强加的实质错误依赖。当前产物未执行正式确认和进入学习，故不把这些规划依赖当成已验证的教学上下文传递或运行期解锁行为。

入口基础被标为假设，正文反复注明不认证掌握；任务书快照仍记录 `taskBrief=null` 并采用 Domain 的原目标。列表字面量、append、嵌套下标等需要时补讲。对于只自述基础的模拟用户，这比把全部相关能力直接记成已掌握更忠实；是否足够帮助某个真实新手仍未观察。

仍有两个需要保留的限制：

1. Stage 2 的电子表格“复制一行结构／复制单元格内对象”和文件夹快捷方式类比没有指定具体系统与复制行为。不能把这些系统一概当成 Python list 的引用语义。该文本适合保留为待限定的可选探索问题，不能当作已核实的等价结论。实际 Stage 2 知识报告也明确未核对该类比，属于可见未覆盖范围。
2. Stage 2 用 `conceptReferences` 承担别名与浅拷贝的对照，其中被引用的 Stage 1 节点只负责别名、不展开浅拷贝。当前路线整体具备两侧知识，后续教学生成仍须同时取得“这次对照的责任”和被引用内容。本实验没有生成教学框架或课堂正文，不能因引用 key 合法就宣称交接已经完成。Stage 3 的 dict 迁移提示、Stage 4 的一般复制／缓存提示同样是探索方向，不是已验证的跨领域规律。

## 来源与独立核对不是同一个证据

课程保存了 [Python 官方 copy 文档](https://docs.python.org/3/library/copy.html) 的实际抓取正文片段，支持赋值建立绑定、浅拷贝保留元素引用、深拷贝递归复制及 memo 的一般说明。抓取材料也含导航等无关片段。来源可访问及片段存在，不等于所有课程句子均获该来源支持。

具体顺序例的输出来自研究者转述，并可按 Python 语义推导和实际运行核验；不能说它是官方文档中的原题。id/is 的详细说明没有在本次抓取的 copy 文档片段中得到逐句支持；人工可核对其本例语义，但不能把这种核对冒充已取得的来源证据。课程提出的教学次序也不属于官方文档已经验证的教学方案。

| --- | --- | --- |

## Direct 路线：已展开内容与停止原因

direct 规划为三个 Stage：绑定与浅拷贝、嵌套共享与槽位替换、综合预测（含独立标记 optional 的 deepcopy 模块）。最终前两个 Stage 各有两个节点，第三个仍为 planned、无实际节点。

Stage 1 的两个例子均可执行且结果正确：别名 append 使两个名字读到 `[1,2,3]`；独立初始化的浅拷贝 append 使 a 保留 `[1,2]`、b 为 `[1,2,3]`。浅拷贝节点在自身开头重述名字绑定，不要求先完成另一个节点；因此没有用排序伪装节点前置。基础来自用户自述，课程还明说诊断只用于调整讲解、不认证掌握或锁定学习。

Stage 2 虽未获得有效语义复核，其**生成内容已经存在且保存**，仍可人工审读。它准确写出嵌套顺序例的两个最终列表，并正确区分修改共享内层和替换 b 的外层槽位。两个节点先回顾所用知识；槽位替换节点显式依赖内层共享节点。示例具备完整初始化，没有把 `b[1]=[7]` 当成修改旧内层对象。其迁移问题把该语句改为 `b[1].append(7)`，沿用同段代码可解，并能直接检验操作目标的区别。

尚需限定的文字不应升级成已复现的知识失败：

- 课程理论骨架把“简单循环跟踪”列入“最小前置链”，但已展开任务都不用循环；用户确实自述会 for，所以不是伪造用户能力，不过把熟悉背景称作必要前置仍过强。实际节点没有增加循环前置锁。
- Stage 2 的“若内层为不可变对象或已替换槽位，则不能直接套用该结论”应明确指共享**修改效果**的前提，不能让人误以为不可变对象一定不共享。其 `newKnowledge` 与具体可变列表例子本身正确。
- 未展开的选学蓝图用“deepcopy 使内层也不再共享”概述原件与副本隔离。应补清“与原件之间”，避免被理解为副本内部的所有共享都会消失；memo 可保留重复引用关系。这里存在解释敏感性，尚不足以把整个蓝图判作确定知识错误，也没有实际选学课堂可审。
- Stage 1 的函数参数迁移提示超出用户明确列举的基础；它是待具体化的探索提问，未被声明为已会知识或主线前置。后续教学若使用，应提供必要解释，而不能据此推断用户已经会函数语义。

来源方面，direct 的官方 copy 页面 `grounding.ok=false`、`error=抓取超时`、正文片段数为 0。课程 `sourceBasis` 如实保留此限制，并把研究者摘要与官方原文区分。课程、骨架、Stage 1 的独立知识报告均为 `no_error_found`，限定到各自实际核对的主张、摘要对照与可复算推导；没有实际运行代码，没有检验真实学习者，也没有覆盖未来 Stage 2/3 正文。这些限定与观察一致，不能把来源缺失自动等同于语义错误。

第 11 次 Provider 调用成功生成 Stage 2；第 12 次 `roadmap_stage_critique` 在 Provider 层 `fetch failed`，无 HTTP 响应及 usage。生产入口随后返回 HTTP 200 包装体，但 `reviewState=unavailable`、`qualityReview.availability=unavailable`，报告写明“AI 语义复审暂不可用；这不是路线内容缺陷”。独立知识核对尚未执行，状态为 uncertain。研究脚本按该实际响应立即停止，没有继续 Stage 3 或补抽模型。这是可用性失败，不是 HTTP 状态失败，也不是 reviewer 判断 Python 知识错误。

Stage 1 响应与专门重载的完整草稿相等。Stage 2 没有专门的 `stage-2-reloaded.json`，因为停止门先触发；但最终 `domain.json` 中持久化的 `roadmapDraftJson` 与 Stage 2 响应草稿逐字相等，证明候选已保存。最终状态为两个 expanded、一个 planned，`mapRevision=0`、`roadmapStatus=draft`、`courseDesignConfirmedAt=null`；终态断言 `formalNodes=0`。不能把保存 expanded 解释成审查可用、用户确认或整个路线完成。

这不是仅变换 thinking 的干净因果比较：来源抓取成败不同，实际材料不同，后续候选规模（4 个／3 个 Stage）、提示长度、重试路径和停止点也不同；每模式仅一条实际路线。不能由总量或完成率推断一般性的成本比、稳定率或教学质量优势。

全实验终态 `run-complete.completed=true` 表示研究脚本正常收尾；同时明确 `allCandidateRoutesGenerated=false`、`semanticAcceptance=false`、`realLearnerOutcomes=false`、`formalAcceptancePerformed=false`。四路线合计 81 次实际 Provider 请求，未超过 96 次预算，源码冻结核验通过；清理记录确认临时设置删除、原设置未变、环境与 fetch 恢复，外键检查无违规。以上是实验与数据边界证据，不代替路线内容验收。

## 本轮能证明与不能证明

已观察到：真实生产入口可生成完整窄域候选（thinking），也可能在中途复核不可用而停止（direct）；两者已展开部分的主线关键代码语义正确，deepcopy 没有被接成主线前置；候选保存可追溯，无正式地图写入。也观察到：独立核对会因 JSON、目标合同、输出预算及响应读取问题失败，探索类比与若干概述仍需限定。

不能据这两条路线声称输出稳定、AI 能可靠自证、教学交接无遗漏或真实用户已学会。材料给出了核心例子的正确结论，本次没有无材料条件、重复采样、真实学习者或延迟迁移比较；不能得出 thinking 优于或劣于 direct 的一般结论。
