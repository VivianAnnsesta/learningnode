# 从失败机制到可检验的改进

日期：2026-10-28。对应目标：真正研究出解决 EnglishNode 项目难点的办法。目标仍在进行，本文记录机制证据与当前实现，不作为产品效果通过声明。

## 本轮改变了什么认识

上一轮主要给出了教学方案和比较办法。本轮先检查真实失败，再运行实际配置模型的对照。已经可以排除一种过于笼统的解释：现有问题不能全部归结为模型随机、需要反复生成直到收敛。

当前反馈链有一个可确定的信息损失：生成时见到原题、用户回答及帮助曝光，核对时却只留下反馈文字和一般课程上下文。对于同一反馈，用户实际回答不同可能使它分别正确和错误；如果两种情况传给核对器的内容逐字相同，单靠核对器就无法可靠恢复这种区别。这是输入缺失，换成更严格的评价措辞也不能补回事实。

真实模型实验进一步显示：补入原始交互能改善部分判断，但仍有模型读懂用户原话、却因为“一般教学提醒正确”而放过错误归因。这是审查任务对“正确”的定义不完整。另一类失败是理由和更正正确、顶层 verdict 却写成无错，属于报告不能执行。它们需要分别处理，不能混成一个质量分数。

## 已实际检验的干预

第一轮在冻结的成对诊断病例上只改变核对器是否得到当次交互。模型、候选反馈、提示措辞、输出合同和采样条件保持相同。第二轮两臂都得到交互，其中一臂额外明确：反馈对用户原话、帮助和任务承诺的归因也是核对对象；参考可能出错；总体 verdict 要与实际 finding 一致。

病例覆盖运算回答、复合条件、逻辑方向、开放观察、帮助曝光和任务承诺。正确与错误病例成对存在，避免把全部拒绝当作质量提升。输入和判据在调用前冻结；判据没有送给模型。第二轮是在看到第一轮失败后设计，属于开发实验，不能冒充未见验证。

详细次数、当前运行结果与成本代理见[当前状态](../../CURRENT_PROGRESS_AND_DIFFICULTIES.md)；完整解释及反例见[逐份输出审读](2026-10-28-context-experiment-review.md)。两轮的请求、原回应、输出校验与临时设置清理证据分别保存在[第一轮](../../web/test-results/feedback-context-2026-10-28-1793176069255/summary.json)和[第二轮](../../web/test-results/feedback-context-2026-10-28-1793176309133/summary.json)。实验通过生产 Provider 适配器调用模型，未走完整产品服务或桌面流程。

第二轮确实减少了前一轮的漏判和报告冲突，但“按本题帮助记录的独立作答”产生了新的争议：模型可能把有限范围的陈述扩成对所有外部帮助的断言，病例本身也没有彻底消除“记录”与“真实行为”的歧义。原标签与原结果均保留，不以事后改标签提高成绩。真实评价需要保留“依据有争议”这一事实，而不是强迫每项成为一个确定分数。

## 可落到现有系统的办法

1. **同一份实际证据贯穿生成和核对。** 保存原题、原始输入、绑定材料版本、提交时帮助与实际来源；历史例子和后续曝光明确区分。参考回应保持可质疑。这样修的是证据传递，不要求新建一套智能体体系。
2. **分开检查事实、归因、报告和行动。** 一般原理正确不代表用户被评价正确，正文正确不代表 verdict 或补讲建议正确；有效 JSON 也不代表结论成立。
3. **把完整反馈作为更正单位，并记住已经确认的错误。** 自动核对现已覆盖正文、用户表现描述、不确定性、判分、行动及新活动；有效替换需要整体重新核对，才可恢复正确判分。报告失败、更正未核实或有已确认未解除的错误时，不继续执行旧判断和行动。手动核对先保存原反馈的确定错误，再尝试更正；之后不确定、连接失败或一句“未发现错误”都不能抹掉原错误记录。撤回旧判断与产生了正确判断是不同结果。
4. **资料与实际尝试绑定。** 失败后同号重试可以使用新资料，但本次来源快照必须同步更新，旧调用原文继续保留。否则后来的审查连自己正在核对哪一版依据都不确定。
5. **用不同性质的证据检验不同问题。** 运算和逻辑案例用计算、反例或推导；引用用实际片段；用户归因用原话；任务要求用已展示的承诺；真实学习改善最终用真实学习者的表现。模型评价是待验证工具，不充当所有问题的最后标准。

实现决定见 [ADR 0026](../adr/0026-material-grounded-planning-and-independent-knowledge-review.md)，当前代码和验证情况只以状态文档为准。此次没有新增正式地图写入路径、自动确认、永久掌握认证或更宽松知识门禁。

## 完整反馈和运行模式带来的新证据

上述证据绑定与完整反馈修复已经接入实际服务，连同失败重试快照、动态活动来源和迟到生成保护一起做了隔离数据库回归。真实配置模型也已经过生成、核对、保存及重载。单字段注入实验另外检查正文正确但判分、用户表现描述或帮助归因单独错误的情况；其中部分可以修好并保留正确判断，另一些报告因自相矛盾或无效行动不能执行。组件实验遇到首次无效报告即停止，不等同于实际服务已经耗尽全部修复机会。

更严格的核对还暴露新的误判：模型把用户可以自由选择的新活动，当成系统强制替换任务；有时也声称原题遗漏了实际已经给出的定义。实际服务中因此既有成功保存的反馈，也有在有界核对后仍被阻断的反馈。不能把记录了阻断当成知识质量成功，更不能为通过实验而放宽身份、任务承诺或报告一致性门。逐项原文及局限见[完整反馈结果审读](2026-10-28-whole-feedback-results.md)。

另一个已核实的配置因素是：当前适配器对相应非联网任务默认关闭模型推理模式。对同一冻结输入开启推理后，初次报告的可执行性和若干误判有所改善，但时间与输出用量明显增加。两臂使用同一请求温度，不代表有效采样参数相同：提供方说明推理模式忽略 temperature。该实验没有更改产品默认模式，返回的替换逐份审读但没有经过完整生产更正复核循环，也没有验证整条路线或真实学习效果。原始对照及审读见[推理模式对照](2026-10-28-thinking-mode-comparison.md)，接口语义见[官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

随后已经完成未用于此前提示调整的规划知识迁移诊断：六组成对文本覆盖代数条件、程序执行、观察与因果、分层汇总。两种模式各有一次不可用报告：非推理的一例报告缺字段且判定与自身推导矛盾；推理的一例耗尽实验输出预算，没有最终答案。实际有效更正逐份审读未发现新增确定错误，但部分支持理由仍有统计口径错位或条件措辞过强。实际输入、失败、完整替换与预算边界见[跨题诊断审读](2026-10-28-planning-transfer-results.md)。这使推理模式成为有代价、需按任务验证的候选方案，不能以部分题目改善推出整体路线可靠。

## 规划链中已经修复的确定性问题

课程研究和显式修复以前可能把不同时间的目标、材料、用户意见混用；旧请求返回后还可能覆盖更新后的候选。现已把本次输入及起始候选身份冻结，在保存事务内核对版本。规划入口也不再把先前读到的意见拼入服务后来读取的新输入，或根据旧目标写回重复任务书。修补的是同一次工作所依据的事实，模型能力再强也不应替系统猜测哪一版才有效。

显式课程修复还存在另一条旁路：一份已记录确定知识错误的课程，只修齐结构后会丢掉知识审查，原错误仍在却能继续生成骨架。现显式修复重新核对知识；原文未改的已确认错误继续保留，实际改动后再检验；连接失败或后来一句“未发现错误”不会清除尚未解除的错误证据。完整原候选和报告归档，保存日志失败时停止发布。这些缺陷都有先失败、修后通过的回归，具体数量和原结果以[当前状态](../../CURRENT_PROGRESS_AND_DIFFICULTIES.md)为准。

对“解耦是否不够”的更准确回答是：需要分清输入、内容、评价和保存各自的责任，同时维持它们之间可核验的联系。多拆一次模型调用，如果交接时丢掉原题、混入另一版材料或覆盖了更正，反而增加失真机会。

## 对控制论与信息论的可用借鉴

**先保证判断者能看到区别。** 假设两个用户给出不同回答，而系统传给审查器的原题、反馈及背景完全相同，其中一份反馈实际归因正确、另一份错误；一个只接收这些相同输入的审查器就无法确定区分两种情况。补足原始回答和帮助记录，才使区别可观察。信息论的数据处理不等式描述：在满足马尔可夫链条件、没有额外信息输入时，后续处理不能增加关于上游变量的互信息。它支持保留任务相关证据的设计，但不意味着整理、推理不能提高计算能力；模型已有知识或新检索也须作为额外输入计入。[Duchi 的讲义，第 2.1.3 节](https://web.stanford.edu/class/stats311/lecture-notes.pdf)

**把测量和纠正分开验证。** 控制论的状态估计与可观测性，提示我们先问反馈是否能反映实际问题，再问纠正动作是否有效。这里可以借鉴设计顺序，不能直接套用线性系统的稳定性定理证明自然语言教学会收敛；本项目并没有已知的线性动态方程、无噪声观测或可证明下降的误差函数。[Murray 的状态估计课程](https://murray.cds.caltech.edu/CDS_110b:_State_Estimation)

**让修复获得新的、可检查的约束。** 既有实验发现部分模型在没有外部反馈时反复自改会退步；另有研究通过关键条件反向验证或工具反馈改善特定任务。它们分别研究不同模型、方法和数据，不能概括为“AI永远不能自改”或“接一个验证器就解决”。对 EnglishNode 的可检验推论是：为疑点提供原材料、具体反例、实际程序结果或任务承诺，再检查更正前后的完整内容；单纯增加“再仔细想想”的次数，没有保证每轮更接近正确。[Huang 等](https://arxiv.org/abs/2310.01798)、[ProCo](https://arxiv.org/abs/2405.14092)、[CRITIC](https://arxiv.org/abs/2305.11738)

这也解释了评价闭环可以存在却不能只用一个分数表示。对可计算命题检查结果和条件；对用户归因检查原话；对任务检查所需材料和可接受产出；对教学顺序保留比较与实际学习证据。已确认的错误要能定位和修复，未知要保留为未知，目标和正确部分在修复中保持不变。闭环的每次进展应由新增证据或已验证改动说明，不能由调用次数说明。

## 尚未解决的难点及下一步证据

| 难点 | 当前证据 | 下一步必须取得的证据 |
| --- | --- | --- |
| 路线中的知识条件、覆盖和真实前置 | 新知识诊断已完成；完整候选路线实验正在进行。有限表非推理路线的主例与方向计算正确，仍有基础归因、具体迁移提示补全和控制条件澄清问题 | 完成各路线原产物审读；区分当前计划与实际课堂任务，检查后续教学是否落实了待补数据，不能用局部命中率替代整条路线 |
| 只改正文，判断或行动仍错 | 完整反馈复核、旧错误保留及行动撤回已实现；真实模型能修复部分单字段错误，仍有报告失败和误判 | 在新病例和实际产品循环中，验证正确判断恢复、更正没有引入新错，以及确定错误不会被后续失败掩盖 |
| 材料相关性与条件混用 | 规划请求、入口与保存版本已修补，显式结构修复不再丢弃旧知识错误；跨语言关键词检索仍有限 | 在相同来源预算下对实际材料检索、来源支持和新题条件分别比较；核查规划中的具体例子和待补事项是否传入教学 |
| 模型审查自身误判 | 真实实验已观察漏判、合同冲突、过度解释与无依据错因；新规划诊断又观察到推理预算内无答案 | 含清晰正确控制的实际问题修订；检查是否既能处理有依据质疑，也能拒绝错误质疑；分别报告误判、弃权、新错及调用代价 |
| 教学是否有帮助 | 已有有依据的教学方案，尚无本轮真实学习者数据 | 可自愿参与、低负担的实际使用与新任务观察；不要拿模拟学生或聊天满意度代替学习 |
| 产品链是否保持可靠 | 本轮有组件实验、隔离数据库回归及真实模型经过服务保存/重载的结果；包含实际阻断 | 在新包中验证保存、显式重试和恢复的完整链；旧桌面包不含本轮改动 |

目标没有缩成“修一个反馈问题”。本轮把一部分宽泛的质量疑问变成了可以复现、改善、同时观察副作用的机制；上述剩余问题继续属于原目标。

完整候选路线的预定范围和研究预算见[协议](2026-10-28-route-quality-protocol.md)，已终止的有限表非推理路线见[逐项语义审读](2026-10-28-finite-route-results.md)。该路线最后一次知识核对被研究预算拦住，不能认作生产失败，也没有完整候选链完成的证据。另一个重要区别是：Stage 3 的知识核对其实已识别迁移例子缺交集，语义评审将它作为后续教学补表的待办。下一步须验证这项责任是否实际传递和落实；不能把“审查已提示”写成“练习已修好”，也不能把允许后续备课的规划提示一律当作已发布的不完整试题。

推理模式的有限表路线已完成全部候选生成与保存后重读，实际内容的主例、方向、静态基准比较与选学边界有逐项支持；其自动知识核对却多次在生产预算内耗尽或截断。当前请求只开关 thinking，没有显式设置 reasoning_effort；官方文档说明其默认值为 high，并支持 low。因此，在相同任务和总预算下对比明确的推理强度，是后续可检验干预；目前未运行这项对比，不据此更改产品默认配置，也不声称 low 已提高准确性。[DeepSeek 模式与强度说明](https://api-docs.deepseek.com/guides/thinking_mode/)

针对实际规划交接，随后完成了隔离程序复现：真实会话备课和正文 prompt 没有收到节点的代表例子、常见错误与迁移提示；只读取同域最新报告会遮蔽早期对应节点的疑点；只看重合短句又会把已变化内容的旧判错带入新课堂。比如“以总体计数作分母”和“不以总体计数作分母”共享同一短句，短句出现不能证明原判断仍适用。程序失败证据和待实施范围见[当前状态](../../CURRENT_PROGRESS_AND_DIFFICULTIES.md)，[运行审计](2026-10-28-route-runtime-audit.md)列出实际字段与责任链。下一项修复已先写入 ADR：保留真实任务全文，用服务计算的节点身份、内容与课程责任绑定相关证据；旧报告不靠猜测升级为新证明，既有课堂历史不静默改写。这个办法同时针对信息丢失与错误归属，效果须在修复后的真实教学链继续验证。
