# EnglishNode 全方案再评估：地图生成、完整节点教学与项目可行性

日期：2026-09-06  
性质：研究评估与建议；未成为已接受的产品规则，未实施或通过真实学习效果验收。

本文在 [方法论草案与自审](2026-09-06-learning-methodology.md) 基础上重新审视方案，补充当前代码、第一性原理与业界一手材料。它是辅助文档，不覆盖 CONTEXT、已接受 ADR、顶层设计、当前状态与执行计划。文中的教学准备和学习记录是拟议职责，不预先确立新数据库模型或领域术语。

## 1. 判断与取舍

**在 EnglishNode 当前目标与资源条件下，最值得优先验证的方案是：以可核对的课程依据约束范围，由 AI 生成适合用户的分层地图，并在有教学材料和学习记录支撑的节点中提供适配式辅导。**

这是设计判断，不是已经通过比较实验的全局最优结论。核心价值是降低新手的规划、理解和练习成本；结果仍要以独立学习表现检验。

本轮相对上一版的实质补充：

1. 地图生成需要可追溯的课程内容依据，来源 URL 与短摘要不足以独自承担课程底座。
2. 完整节点教学需要备好的解释、例题、可验证练习与反馈条件，不能只增加一段对话提示词。
3. 教学会话与自己的理解沉淀必须分开；新手应能在沉淀前讲解、练习、出错和恢复学习。
4. 学习内容的组织、练习顺序和个人知识关系承担不同职责；不能都压进一个前置 DAG。
5. 业界可借鉴的是课程依据、教学支架、反馈和评估方式，而不是无条件移植某个产品的通关或追问规则。
6. 技术可实现、受限主题的教学效果、任意领域的可靠性是不同结论；后两者必须逐步取得证据。

## 2. 第一性原理：系统实际要完成什么

### 2.1 学习成果发生在学习者身上

本项目可操作的目标，是让用户在给定条件下能够更独立地解释、判断、解决问题或完成作品，并在以后仍能使用。页面、地图和笔记是支持这一变化的工具。

AI 直接观察到的是回答、操作、求助和时间等有限表现，无法直接读取真实理解。因此每次判断都要带条件：用了什么提示、做的是哪种任务、是否隔了一段时间；未知部分继续保留未知。

### 2.2 知识储备、教学判断和学习者投入各有作用

模型知道某个知识点，提供了讲解与联想的基础。要产生教学结果，还需要合适任务、能理解的表示、足够练习、可信反馈及用户的实际参与。系统可以减少不必要困难，但不能保证用户投入或在固定时间内学会。

所以这里的“高效”需要同时看学习收益、有效练习时间、等待、重复无效帮助和退出。最短路线、最少节点或最长对话都不能单独代表高效。

### 2.3 地图是关于学习前置的可修订安排

概念之间存在类比、因果、对照等多种联系；正式 Domain Map 当前只承载显式学习前置。练习穿插和复习是对内容的再次使用，不需要反向前置边；个人理解形成后的知识关系由正式 Knowledge Graph 承载。

完整地图的“完整”必须相对于已确认用途与范围。一个领域可以有多个合理课程结构，学习者也可以自主选择路径。不存在由节点排序自然推出的唯一正确学习路线。

### 2.4 可行性分层

| 目标 | 本轮判断 | 成立条件或证据缺口 |
| --- | --- | --- |
| AI 研究范围并生成分层草稿 | 技术可实现，已有部分主链 | 尚需更完整的内容依据、范围到蓝图核验和重复生成稳定性证据。 |
| 节点中提供讲解、例题、练习、反馈和恢复 | 技术上可以基于现有系统建设 | 需要教学准备、学习过程记录、沉淀前练习与完整入口，不能仅连接现有 API 即宣称完成。 |
| 对特定起点与主题改善入门效果 | 有外部研究支持可行方向，本项目待验证 | 需要独立任务、真实学习者与适当对照。 |
| 任意领域均专业正确、个性化最优且无需任何外部校准 | 当前不能承诺 | 范围可能开放、资料可能冲突，评价也可能有专业分歧。 |
| 单用户本地优先产品长期可用 | 工程上合理 | 控制调用与资料维护成本，维持既有安全、数据与确认边界；本轮不重做发布认证。 |

以上是逻辑与工程评估，不是当前产品通过发布或教学验收的声明。

## 4. 地图应该如何由 AI 生成

### 4.1 三种方案比较

| 方式 | 优点 | 主要限制 | 本项目取舍 |
| --- | --- | --- | --- |
| 直接要求模型生成完整路线 | 启动简单，表达灵活，能快速展示候选。 | 容易同时遗漏范围和前置，结构校验无法补回模型没想到的内容。 | 保留为研究对照，不作为可靠性的唯一依据。 |
| 完全固定专家课程 | 范围和顺序易审查，复用成本低。 | 个性化空间小，难适应用户用途；直接导入正式地图也不符合 ADR 0009。 | 作为 AI 可用的课程输入与研究参照。 |
| 可信课程依据约束范围，AI 做目标适配与分层组织 | 能结合外部标准、新手目标和逐步适配。 | 需要内容选择、证据组织及转换保真，仍会犯错。 | 当前优先验证的主方案。 |

### 4.2 推荐的生成过程

1. **理解用途与起点。** 用户用自己的话表达用途、投入和背景；AI 对影响方向的歧义提出少量具体选择。专业排除范围由 AI 建议，并解释对预期成果的影响。
2. **研究课程依据。** 查找与目标深度匹配的课程、教材或官方要求，提取相关目录、目标、定义及任务类型。保留版本与出处；对覆盖不足继续定向研究。继续沿用 HTTPS、公网地址、有界抓取等安全约束。
3. **形成可检查目标。** 每个目标说明它服务哪个用途、预期表现、必要前置和来源；列明暂缓、排除与不确定项。另用独立参照检查模型是否遗漏了整个范围。
4. **组织能力与前置。** AI 解释完成后续任务的哪一步需要前置能力。程序核对引用、无环和映射，语义理由依靠内容审查。把关联或建议顺序误当硬前置会增加不必要学习成本。
5. **生成完整 Stage 骨架。** 在声明范围内安排 Stage、Module 方向、关键问题和结果，检查每个目标有承接、每个计划项有用途。语义设计与结构转换可分两步比较，但不预设拆调用必然更好。
6. **用户确认，再逐 Stage 展开。** 用户能看到完整骨架和可理解的取舍；确认表示选择采用。详细 Learning Nodes 只在用户请求时生成，继续绑定 mapRevision、稳定 key 和审查回执。

范围与来源中的不确定性不应隐藏在模糊 Stage 目标里。当前质量门失败时仍按既有有界修复和恢复规则处理，不新增无 AI 建图路径。

### 4.3 必须检查的两类质量

**可由程序检查的保真与完整性：**引用是否存在、是否有环、版本是否一致、声明目标是否有映射、展开节点是否覆盖蓝图、转换是否无声丢字段或数组内容。

**需要外部依据与语义判断的质量：**范围清单是否本身完整、前置是否确实必要、任务是否适合起点、结果是否能通过实际表现检查。给目标附一个 key 不能证明这些判断。

修复应指向明确问题及受影响局部，保留未受影响内容。修复终态重新核对相关依据与结构，并检查是否引入其他缺项；不能以修复者自己说 passed 作为唯一结束证据。产品中的修复次数与可恢复审查继续遵守现有 ADR。

### 4.4 全局视野与细节适配可以共存

全局骨架说明大范围去向，近期 Stage 提供具体可学内容。学习表现可以影响后续讲法与展开建议，但不得悄悄删除正式目标、自动展开 Stage 或改写地图。

综合任务只汇聚自身范围所需分支。一个概念在后续更复杂任务中再次使用是正常学习安排，不需要把复习编码成前置图中的循环。

## 5. 节点如何实现完整教学

### 5.1 节点进入教学前需要准备什么

节点至少要有可用于本次目标的教学内容：目标与起点假设、经过核对的关键解释、适用条件、正例与必要反例、示范过程、引导练习、独立练习及参考判据。内容按学科选择，不要求每个节点都填满一套固定表格。

AI 可以生成和适配这些内容，但课程定义、关键解答与评分依据应尽可能由可核对材料、计算验证或领域复核支撑。不能先随机出题，再让同一回答不经核对地决定答案与评分。

这类教学准备可以在用户展开 Stage 后按需进行，保持该次教学版本稳定；后续有问题形成可追溯修订。角色职责不必一一变成独立 Agent 或常驻服务。

### 5.2 一次节点教学的完整功能

| 环节 | 用户应能实际做什么 | AI 与程序应承担什么 |
| --- | --- | --- |
| 开始 | 选择从基础讲起、尝试问题或继续上次学习。 | 恢复节点与教学版本、已有回答和帮助记录。 |
| 了解与示范 | 阅读解释、看图或例子、询问术语、请求换讲法。 | 用课程材料解释，给具体示范，说明类比边界。 |
| 引导练习 | 作答、查看渐进提示、比较示范、重试。 | 判断当前步骤并提供适量帮助，记录实际提示曝光。 |
| 独立练习 | 在明确条件下完成新的任务。 | 保留题目与答案版本，依据判据评价，允许正确的不同解法。 |
| 纠错与再尝试 | 查看错误位置、补必要前置、再做不同例子。 | 区分可能原因，避免只说“理解不深”，检验帮助是否有效。 |
| 总结与沉淀 | 写下自己的理解，明确确认是否沉淀。 | AI 可辅助检查；确认后按既有规则首次写 seen。 |
| 后续使用 | 返回地图、再次练习、复习或应用到后续任务。 | 保留条件化表现，给可选支持；不自动写高阶掌握状态。 |

这不是一条强制通关序列。用户可以选择讲解、练习或暂停，已会的部分可以少用帮助；未满足前置继续只警告。独立练习完成也不是新增的 KnowledgePoint 首次沉淀门槛。

### 5.3 最小页面组织

建议使用同一个节点工作区：上方显示当前目标和课程位置，中间呈现当前讲解或练习，下方是回答区域和少量明确动作，例如“从基础讲”“给我提示”“看示范”“换个例子”“继续练习”。回答反馈展示具体依据，个人理解总结单独保留。

AI 对话应能引用当前题目、用户上一步回答、已展示提示与课程资料。使用者无需懂得如何拼接提示词，也无需先沉淀知识才能练习。暂停、刷新、请求失败后应能继续同一教学任务，避免题目、答案和评价错配。

### 5.4 最小教学过程记录

研究与未来实现需要区分：节点与教学版本、练习任务与参考答案、每次作答、辅助程度、AI 反馈与依据、用户修订、当前会话位置、时间和错误。

这些记录服务恢复与教学判断。AiCallLog 解决调用追踪，LearningProgress 解决状态事实，两者都不能单独代替完整教学过程。这里提出的是职责缺口；新增正式存储必须先走领域定义、ADR 与状态文档流程。

### 5.5 学科差异与完整任务

| 学习内容 | 合适的主要活动 | 需要警惕 |
| --- | --- | --- |
| 概念与关系 | 具体例子、图示、正反例比较、解释与判断。 | 会背定义但不会辨认；类比被当成定义。 |
| 数学或编程操作 | 示范、分步练习、逐渐撤提示、独立解题与结果核验。 | 看懂步骤被当成会做；只测最终答案忽略错误来源。 |
| 语言与记忆内容 | 有意义的使用情境、提取练习、重复接触与适量明确解释。 | 把语言方法无条件推广到所有学科。 |
| 开放分析与创作 | 范例比较、作品、评价标准、修改与理由讨论。 | 强求单一标准措辞，或把偏好写成客观真理。 |

节点间还需要完整任务，检验学习者能否选择并组合已学内容。原子问题应降低局部困难，而不能让课程失去整体用途。参见 [4C/ID 的完整任务与支持信息框架](https://www.4cid.org/about/)。

### 5.6 一个贯通地图与教学的示例

以下是待试教的设计示例，假设学习者会基本运算；不表示零基础效果已经验证。目标是能借助小区间平均变化率解释某一时刻的瞬时变化率，暂不覆盖整套求导法则。

地图可以让“读懂位置—时间函数”和“计算区间平均变化率”两条准备分支汇入“理解瞬时变化率”，最后用一个简单运动问题组合使用。两条准备分支没有必要仅因显示先后而互设前置；如果用户已有相应能力，可以直接尝试后续内容。

在瞬时变化率节点内，先用位置函数 s(t)=t² 示范：从 t=1 到 t=1.1 的平均变化率是 2.1。随后请用户计算更短区间并解释数字对应的是区间还是时刻。AI 根据具体回答选择帮助：

| 观察到的表现 | 下一步教学动作 | 还需要观察什么 |
| --- | --- | --- |
| 无法代入或读取函数值 | 示范一次函数取值，再让用户完成另一组。 | 错误是否来自符号理解，而非变化率概念。 |
| 只算位置变化，没有除以时间变化 | 比较相同位置变化、不同用时的两个例子。 | 能否说明“每单位时间”的含义并重新计算。 |
| 能算出 2.1，却直接称其为 t=1 的瞬时值 | 对照更短区间，以及 t=1 左侧的小区间。 | 能否区分区间平均值与逐步逼近的点上变化率。 |
| 依赖刚展示的完整解答答对 | 给一个不同数字或表述的新任务，减少提示。 | 是否能够独立使用方法；不能只凭刚才答对判定学会。 |

一次错答只是选择下一步帮助的线索，原因需要后续回答澄清。展示越来越接近的数值是直观支持，不替代以后对极限定义的正式学习。结束时用户可以写下自己的解释并选择沉淀；另用未展示答案的新任务和后续复习记录检查保留情况。这一小样本首先检验近迁移，不能据此宣称已经掌握全部导数应用。

## 6. 业界与学习科学对照

| [Khanmigo 数学与辅导更新](https://blog.khanacademy.org/khanmigo-math-computation-and-tutoring-updates/) | 将已有练习、步骤、提示和解答提供给导师作为上下文，并改善图形内容表示。 | 建议优先补充可靠教学材料及当前任务上下文；官方报告的内部改进不能直接量化为本项目学习收益。 |
| [MATHia 学生支持](https://support.carnegielearning.com/help-center/math/home-connection/mathia-support22/article/ways-to-get-support-when-working-in-mathia/) | 提供分步示范、按需提示和针对错误的即时帮助。 | 说明完整支持不应只等用户提出高质量问题；不照搬其掌握分数或通关限制。 |
| [Duolingo 教学方法](https://blog.duolingo.com/duolingo-teaching-method/)与[课程标准说明](https://blog.duolingo.com/how-well-does-duolingo-work/) | 结合课程标准、互动活动、个性化与持续参与；主要语言课程参考 CEFR。 | 借鉴标准约束和小步可行动任务；不能由语言产品实践证明通用课程自动生成有效。 |

| [LearnLM 与 Eedi 探索性 RCT](https://arxiv.org/abs/2512.23633) | 在数学平台中研究 AI 辅导；专家监督并可逐条修改 AI 草稿。 | 支持受条件约束的可行性，必须计入人工介入；不能当作完全无人监督的通用导师证据。 |

学习方法上，建议采用以下组合：目标与评价对齐安排课程；新手阶段提供明确解释和示范；用引导练习逐渐转向独立活动；按任务需要采用提取、间隔、变式和完整任务。它是一组设计依据，具体组合需要按学习者表现检验。

[CMU 对齐指南](https://www.cmu.edu/teaching/assessment/basics/alignment.html)支持课程目标、教学与检查相互对应。[IES 实践指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)列出示范与练习交替、具体与抽象结合、间隔和提取测验等建议，并区分证据强度。不能把某个单独教学法、始终追问或始终给答案设为所有节点的唯一模式。

## 7. 项目中的矛盾与解法

| 矛盾或张力 | 会发生什么 | 建议解法 |
| --- | --- | --- |
| 新手缺少专业知识，却需确认专业规划 | 用户无法发现整章遗漏，确认看起来像质量背书。 | AI 提出专业范围，用户确认用途和采纳；内容核验与用户授权分开。 |
| 用户思考优先，但完全不会时无内容可思考 | 学习变成长时间空白输入与反问。 | 提供讲解、示范和提示后的重试；思考发生在可理解任务中。 |
| 入门需要练习，现有 practice 要先关联 KnowledgePoint | 练习放到了沉淀之后。 | 将沉淀前教学练习与沉淀后迁移挑战分清；不能用提前物化知识点绕过。 |
| 学习路径需要适配，但正式地图必须稳定 | 每次错答改图会破坏用户认知与版本保护。 | 当前节点内适配先行；目标或前置有结构证据才形成 Map Draft。 |
| 自主选择与新手需要指引 | 没有帮助会产生选择负担，唯一推荐又违背现有边界。 | 给可理解的多个入口、所需前置和选择理由；不锁定或偷偷产生唯一下一节点。 |
| 追求完整知识，用户时间有限 | 课程无限扩张，远期内容占用开学前等待。 | 完整性相对于声明目标；全局骨架先确认，详情逐 Stage 展开。 |
| 前置是 DAG，实际学习要复习和循环使用 | 若混在一起会产生假依赖或环。 | 正式前置、学习活动顺序和知识关系分开处理。 |
| 同一 AI 规划、出题、评分 | 自证闭环可能共享遗漏与误判。 | 外部参照、经核对答案和保留任务参与校准；不同模型只增加视角。 |
| 需要规模化，但每次都要求专家审核 | 人工成本被包装成 AI 自动能力。 | 复用经过核对的课程输入和参考材料，记录新增内容与人工介入；未知领域保留能力声明边界。 |
| 会解释或点击沉淀，被当成真正掌握 | 记录事实被误读为能力证明。 | 保留 seen 语义；独立、提示下及延迟表现分别记录，不自动高阶晋级。 |

其中多数是可通过职责分离解决的设计张力。“对任意领域完全正确且最优”的承诺则缺少可操作边界，不能通过增加提示词消除。

## 8. 最适合当前项目的实施组合

### 8.1 建议保留与优先补齐

保留现有分层地图、用户逐 Stage 展开、显式 DAG、版本化确认和最小知识沉淀。优先补两条能共同验证的能力：

**课程准备：**AI 研究匹配用途的资料，形成有来源与检查任务的目标，组织完整骨架，核对转换保真，并为近期教学准备可靠内容。

**持续教学：**用户在同一节点中获得解释、示范、沉淀前练习、反馈、再尝试和恢复；过程有记录，AI 获得与当前任务相关的上下文。

独立验收对这两条能力分别校准，再验证联合运行。先证明有用的组合，再决定是否需要更复杂的学习者模型、多 Agent 编排或微调；不能把这些技术作为潜力被释放的先决条件。

### 8.2 有限调用与内容复用

研究资料与教学材料可按用途、来源版本和目标复用；个性化主要体现在起点、讲法、例子、练习和后续建议。AI 首轮不生成所有远期课程正文，每个用户回复也不必先经过多个模型投票。

当内容发生变化或出现可复核错误时，修订对应部分并记录影响；程序负责可靠保存、版本、预算和错误恢复。任何正式写入继续使用正式领域 API 与既有认证边界。

### 8.3 直接聊天仍应作为研究基线

用同样资料、模型和目标比较通用 AI 对话与 EnglishNode：项目应在持续上下文、恢复、课程依据、练习与知识记录方面提供实际价值。如果组合工作流只增加等待而没有提升学习或可用性，应简化相应环节。

## 9. 下一步可以执行的研究任务

首选一个有可靠材料的小主题，把目标、AI 完整骨架、近期教学内容、练习与参考判据、会话恢复和独立检查做成一个连续样本。例：导数的直观意义与简单应用；范围不扩展到整门数学一。该样本需要贯穿若干有真实联系的节点，才能同时检查地图与教学。

建议按顺序验证：

1. 对照外部范围检查 AI 原始地图，保留失败样本，并区分 AI 原稿与人工修订。
2. 在同一可核对课程上验证完整节点教学；特别检查沉淀前练习、帮助曝光、答案判据与刷新恢复。
3. 使用真实新手的独立与延迟任务评估效果；与固定教学或通用 AI 基线比较，记录前测、实际用时、退出与人工介入。
4. 再验证自动生成地图与教学联合运行，并使用未参与调优的主题检查迁移。小样本只提供探索线索。

研究不能只靠模型扮演学生。若缺少合适参与者或专业参照，可以先完成材料和流程核对，但学习效果保持未验证。实验设计和保留集规则沿用上一版方法草案中的限制。

## 10. 需要先修改文档再实施的边界

沉淀前练习语义、教学过程存储、课程目标与节点教学的绑定、Task Brief 中“尚未指定”的表达，以及任何地图调整接口，若进入实施都应先完成对应 CONTEXT/ADR/状态与计划修订。研究文档不授权绕过现有接口或确认规则。

本轮没有实施这些修改，也没有运行真实数据库、真实 AI 教学或浏览器验收。本评估由主助手完成资料与代码核对及自审，不作为独立教学效果审查证据。
